# 阶段3实现说明

## 相比阶段1的关键变化

| 阶段1 | 阶段3 |
|---|---|
| 预先准备本地 `places/roads` | Planner 声明数据需求，运行时下载 |
| Chroma + 规则加权 | Dense Top-20 + Cross-Encoder Top-4 |
| 自定义 JSON Planner | DeepSeek 原生 Tool Calling，JSON fallback |
| 固定成功路径 | 条件路由、错误分类、限次重试和重规划 |
| 执行成功即总结 | Evaluator 通过后才允许总结 |
| 公共 outputs 路径 | `task_id` 隔离的工作目录 |

## 动态高校道路任务

1. 下载行政区边界。
2. 校验 Polygon、CRS 和查询面积。
3. 下载边界内的 OSM 大学/学院点。
4. 自动选择本地 UTM 投影。
5. 对全部点建立缓冲并合并。
6. 下载缓冲区相交道路。
7. 道路投影到缓冲区 CRS。
8. QGIS 裁剪并统计道路长度。
9. Evaluator 检查结果文件和字段。
10. LLM 只基于统计 JSON 生成回答。

江苏省城市的道路默认来自运行时下载的 Geofabrik 江苏 PBF，首次约需下载70多MB，之后使用缓存。
高校点仍来自 Overpass。没有省级静态提取映射时，系统才使用分网格 Overpass 道路查询。

## 技术边界

Nominatim 和 Overpass 是在线公共服务，可能限流或暂时不可用。项目适合原型和
面试演示，不适合直接作为高并发生产下载服务。生产环境应使用自建 Nominatim、
Overpass 或区域 PBF 数据管线。
