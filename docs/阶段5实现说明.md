# 阶段 5：多轮对话与记忆

## 1. 目标

阶段 5 在阶段 4 后端之上加入多轮对话。用户不必在每一轮重复区域名称，同一会话可以完成：

1. 帮我计算南京市的面积。
2. 它周围有哪些城市？
3. 再统计这里面的高校数量。

第二、三轮由 `context_resolver` 从结构化记忆中的 `current_region=南京市` 补全，不依赖模型猜测。

## 2. 两层 LangGraph

外层 `conversation_agent.py` 负责会话语义：解析区域和任务类型、决定澄清还是执行、维护记忆。
内层 `langgraph_agent.py` 负责 GIS：RAG、规划、schema 校验、工具执行、结果评估和回答生成。

这种分层避免把历史消息直接塞进 GIS Planner，也使指代错误能在下载数据前被拦截。

## 3. 记忆存储

MySQL 是业务真相源：

- `conversations`：标题、结构化状态、压缩摘要、轮次数。
- `conversation_messages`：完整用户/助手消息。
- `conversation_turns`：将任务和会话关联。

LangGraph `SqliteSaver` 使用 `conversation_id` 作为 `thread_id`，检查点默认写入
`outputs/checkpoints/state5.sqlite`。服务重启后，MySQL 会恢复结构化记忆和最近消息；检查点用于保留图状态。

## 4. 上下文控制

每轮仅加载最近 6 条原始消息。更早消息压缩到最多 2000 字符，结构化槽位独立保存：

- `current_region`
- `current_dataset`
- `previous_task_type`
- `previous_result`
- `previous_artifact`

因此对话增长不会导致传入执行链的上下文无限增加。

## 5. 可靠性边界

若用户说“它”或“这里”但当前会话没有区域，系统返回澄清问题，不执行 GIS 工具。显式新区域优先于旧记忆。
不同 `conversation_id` 的状态完全隔离。

相邻区域任务基于项目内 GADM 4.1 学术测试夹具，目的是稳定验证多轮工作流，并非现行官方区划接口。
面积、高校和道路任务仍使用 OSM 数据，结果必须保留数据口径说明。

## 6. 关键文件

| 文件 | 作用 |
|---|---|
| `geoai_agent/context_resolver.py` | 提取区域、识别意图、补全指代或触发澄清 |
| `geoai_agent/conversation_agent.py` | 外层会话 LangGraph 和 SQLite Checkpointer |
| `backend/models.py` | 会话、消息、会话任务关联表 |
| `backend/service.py` | 任务创建、会话恢复、执行、记忆更新和历史压缩 |
| `backend/api.py` | 会话 API 与带 `conversation_id` 的任务 API |
| `geoai_agent/workflow_factory.py` | 包含相邻区域在内的受控工作流模板 |
| `tests/test_conversation_memory.py` | 多轮继承、隔离、覆盖和澄清测试 |
