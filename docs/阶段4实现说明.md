# 阶段4实现说明

阶段4没有修改阶段3的GIS智能体核心，而是在外层增加服务化能力：

1. FastAPI负责接收任务和查询状态，不直接执行QGIS。
2. MySQL保存任务、步骤、检索、模型调用、产物和评测记录。
3. 独立Worker轮询并领取`PENDING`任务，执行原有LangGraph工作流。
4. 每个任务继续使用独立`outputs/tasks/<task_id>`目录。
5. 相同`user_id + Idempotency-Key`只创建一个任务。
6. Worker异常退出后，超时的`RUNNING`任务会被明确标记为失败。

为了便于本地学习，数据库层同时支持SQLite；这只是单Worker演示后备，正式
阶段4路径仍是MySQL。当前版本没有引入Redis/Celery，原因是MySQL轮询Worker
已经能验证异步执行、状态持久化和进程解耦，等任务量增长后再增加消息队列。
